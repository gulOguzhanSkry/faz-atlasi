Date: 2 November 2026. Independent test agent; production code was written by the coordinating agent and implementation agents. This record covers local automated evidence. It is not metallurgical validation, a browser screenshot review, a published-site check, or approval of the remaining stages.

## Evidence

- Constituents: 6,561 regular C/T samples resolve with total mass, carbon mass balance and each individual source phase inventory conserved to 1e-8. Source phase objects remain equal to the real solver output. The grid has zero unavailable states; 50 rounded cementite-endpoint states explicitly fall back to source phases rather than a constituent ancestry claim.
- Boundaries: another 18,997 cases at every source-row region endpoint, ±1e-6 composition neighbours and region centres conserve the source inventories. This addresses narrow fields that a regular grid can miss.
- Invariants: eutectoid, eutectic and peritectic progress cover endpoints and neighbouring composition ranges. Separate stoichiometric oracles check actual phase amounts at ξ = 0, 0.25, 0.75, 1, in addition to monotonicity and mass balance. ξ is reaction progress, not elapsed time. Nearby temperatures do not incorrectly demand ξ.
- Portable query: `web/faz-durumu.js` has full JSON result equality with the original browser query on 6,561 samples and exact invariant composition/temperature neighbours.
- UI: TR/EN constituent labels, alloy-isopleth and empirical-alloy disablement, exact-invariant fraction-card hiding, shared resolved phase inventory, progress reset after moving away, and preservation of the range element during dragging are checked in a DOM simulation.

- Geometry: weighted nearest-seed ownership is checked against an independent distance oracle, deterministic seed generation and tie handling. Rasterized grid slices agree with continuous ownership along all three axes.
- Occupancy: at 0.2 / 0.45 / 0.76 / 1.2 / 3.0 / 4.38 / 5.0 wt% C, 650 °C, every centre of the 24³ economy grid agrees with continuous phase and constituent sampling. Constituent counts have less than one cell quantization error; phase counts are independently bounded by accumulated per-constituent rounding. - Shared sections: each pixel in x/y/z slices maps to the same model sample and grain identity. State changes invalidate stale slices; unresolved states produce no phase labels.
- 2D appearance: phase/constituent/grain identities are unchanged by appearance mode, optical effects and repeated rendering. ## Cross-platform CI correction

The initial v1.2.0 Windows run passed 31/31 locally, but the coordinator reported Linux GitHub Actions at 30/31: the trace report compared a hash of a CRLF working file with an LF Git checkout. The earlier local pass therefore did not establish cross-platform reproducibility.

The revised text-hash contract is explicit: `UTF-8 text with LF line endings (Git text normalization)`. The independent test normalizes CRLF to LF, asserts the report's declared `hashBasis`, checks LF/CRLF equivalence, and proves that an actual numeric content change still changes the hash. The original numerical guard remains: every recorded boundary pair, carbon difference and branch maximum must agree with the actual original source query.

The additional provenance audit compared working files with Git objects. Six of seven research-JSON manifest entries contained Windows byte hashes/counts that differed from Git LF blobs. The seven preserved module entries mixed LF and CRLF provenance. These text manifests are now subject to the same declared canonical-LF hash checks, with canonical UTF-8 byte counts where recorded. External database/TDB raw provenance hashes remain raw-file identities; they must not be silently reinterpreted as normalized text hashes. Pinned release-artifact manifests likewise retain their declared byte-exact artifact meaning.

`node tests/verify-lf-checkout.mjs` first verified the portability fix at 33/33. The latest run, including the subsequent mobile/gallery tests, constructed a temporary LF-only copy of 182 current nonignored files, normalizing 163 text files while preserving binary media: **39/39 passed**. The normal Windows working tree independently passed **39/39**. The diagnostic reused only the installed development dependencies and removed its temporary copy afterward. These runs reproduce the checkout line-ending condition on the development machine; they are not a Linux OS test. The coordinator owns the replacement `v1.2.1` pin and actual GitHub Actions rerun; no successful remote rerun is claimed here before verification.

## Remaining acceptance limits

- An arbitrary cut through a genuine 3D morphology does **not** have the global sample's exact mass fraction as its area fraction. The current renderer preserves a true shared volume/cut and discloses that section area is not whole-sample mass or volume fraction. This is a deliberate difference from the stage 3B plan's exact per-cut area-budget requirement. Passing voxel mass budgets does not prove density-correct physical volume fractions.
- Geometry-field caching resolved the initial warm-section performance finding. Latest Node v24.19.0 balanced measurement: first occupancy update 175 ms plus first 128² section 114 ms; warm updates 2.5–41 ms and warm sections 4.3–12.6 ms. A warm update plus one section remained below 54 ms on this machine. This excludes six-face drawing, the canvas presentation and WebGL; it therefore does not establish the full live <60 ms browser criterion. These timings are diagnostic, not a flaky unit-test threshold.
- Stage 5 records a material source-vs-candidate L+C endpoint discrepancy up to approximately 0.07752 carbon weight-percentage points around 1223.47 °C. Source-table conservation and query equality do not certify that phase boundary's physical accuracy or repair nearest-topology-row interpolation.
- The tests establish numerical consistency and deterministic illustrative geometry. They do not establish realistic morphology, grain dimensions, lamellar spacing, CCT/TTT kinetics, graphite/bainite/martensite formation, experimental thermodynamic accuracy, or engineer acceptance of visual realism.
